# Advanced implementation prompt — API traffic intelligence

Act as a principal API-security architect and senior Python engineer. Extend this repository's original, explainable traffic classification MVP to production-grade, defensible API discovery. Preserve existing behavior, tests, UX flows, and data-export contracts. Do not copy any proprietary Noname Security code or imply parity with proprietary functionality.

**Phase 1 — Integration and schemas.** Build versioned traffic adapters for Envoy, NGINX/OpenResty, Kong, Apigee, AWS API Gateway, Azure APIM and sanitized HAR/JSONL. Apply schema validation and canonicalization across HTTP/1.1, HTTP/2, gRPC, GraphQL, SOAP, JSON-RPC, WebSocket upgrade, MCP, SSE, REST. Define a source-agnostic event model with tenant, request identifier, timestamp, method, hostname, normalized path, response status, request/response media type and safe metadata. Default deny on payload logging; strip cookies, auth headers, tokens, personal data. Support deduplication, streaming backpressure and dead-letter handling.

**Phase 2 — Hybrid discovery.** Implement extensible feature extractors and a deterministic high-precision rule layer, followed by a calibrated statistical classifier trained only on verified labels. Classify API / NON_API / UNIDENTIFIED by explicit confidence thresholds and high-risk conflict detection. Detect machine-oriented HTTP semantics, structured response contracts, temporal and client-behavior patterns, method distributions, path hierarchy, endpoint cohesion, API specifications, gateway provenance, and content negotiation. Do not equate JSON with API or assume POST is API. Infer parameterized route templates and version families. Track endpoint inventory with evidence lineage, timestamp, observed methods, ownership, active/dormant states and shadow API flags.

**Phase 3 — Streaming.** Connect live collector(s) through secure authenticated endpoints; use queues and workers for high-rate ingestion. Strictly differentiate live ingress, file-only batch mode, and inspection off (fail closed for incoming ingest); preserve passive historical query. Add pause/stop states, health/lag indicators, retry policies, rate limits, source auth, TLS termination and RBAC. Document throughput measurements against representative anonymized loads. No packet decryption or transparent interception without explicitly deployed authorized infrastructure.

**Phase 4 — Vendor benchmark.** Create pluggable and versioned schema mappings for actual vendor exports. Support robust ID joins first, then strict endpoint/method/time-window matching; never fabricate matches. Clearly separate *agreement with vendor* from *ground-truth accuracy*. Report per-class precision, recall, F1, macro/micro-F1, confusion matrix, endpoint coverage, unmatched records, confidence calibration, and error slices. Provide reviewer work queues for false positives, false negatives, and abstentions; adjudicate disputed vendor labels.

**Phase 5 — Continuous learning.** Add a human-reviewed contextual-bandit policy on uncertain examples, with explicitly defined state (confidence, features, source context), allowed actions (predict API, predict NON_API, abstain, request review), reward (+1 verified correct, -1 verified wrong, small cost of review, large penalty for confident mistakes). No reward from self-predictions or raw vendor disagreement. Maintain an immutable, dated reward and policy ledger. Use strictly separated time-sliced train/validation/holdout data; prevent leakage across identical endpoint families. Perform offline policy evaluation or bounded canary rollout with statistically justified sample sizes, shadow-mode comparison, promotion on per-class nonregression, drift alarms and automatic rollback. Do not claim reinforcement learning improved accuracy until holdout evaluations demonstrate it. Retain confidence-based abstention.

**Phase 6 — Verification.** Create thorough unit/integration/property tests for positive/negative paths, schema drift, retries, concurrency, duplicate ids, malformed files, privacy masking, large batch limits, bias, low-signal abstention and rollback; add deterministic fixtures. Containerize and deploy a read-only dashboard with SSO/RBAC, tenant isolation, audit trails and safe secrets management. Add a reproducible benchmark command that generates quality metrics only from verified labeled records and emits a signed, timestamped report.

**Acceptance:** Each phase must ship production-quality code, automated tests, documentation, operational runbook, performance/accuracy evidence and explicit limitations. No hard-coded claims of >95% accuracy; holdout evaluation determines results. Keep a working, reversible release after each phase.
